# 🐛 Bugfix: Daily Trader Optimizer - Ranges Too Aggressive

**Date:** October 13, 2025
**Optimization Run:** Generation 80/80 completed with 0 trades

## Problem Summary

The first full optimization (100 pop, 80 gen) completed successfully but **ALL individuals resulted in 0 trades**, indicating the parameter ranges were too aggressive.

## Root Cause

### Initial Aggressive Ranges (BROKEN ❌)
```python
'dist_below_ma_pct': 0.05-0.15  # 5-15% - TOO TIGHT!
'tp_pct': 0.02-0.05             # 2-5%  - TOO SMALL!
'sl_pct': 0.01-0.03             # 1-3%  - TOO SMALL!
'time_stop': 5-20               # OK
```

**Why 0 trades?**
- `dist_below_ma_pct` of 5-15% means price needs to be very close to MA (within 5-15%)
- BTC rarely gets that close to MA220 in daily timeframe
- Even when it does, small TP/SL (2-5%, 1-3%) exit too quickly
- Result: Signal criteria almost never met = 0 trades

### Evidence from Grid Search
Grid search results showed best configs use:
- `dist_below_ma_pct`: **0.05-0.20** (5-20%), with 10% being optimal
- `tp_pct`: **0.08-0.12** (8-12%), with 10% being optimal  
- `sl_pct`: **0.08-0.12** (8-12%), with 10% being optimal
- Champion config: dist=10%, tp=10%, sl=10% → **18 trades**, PF=2.78

### Manual Validation
```bash

# Test with aggressive params
$ python src/mr_backtest.py --csv data/BTCUSDT_daily.csv --variant base \
  --tp_pct 0.03 --sl_pct 0.02 --ma_len 220 --dist_below_ma_pct 0.10 \
  --time_stop 10 --atr_mult 1.5 --no_breakeven

Result: ❌ 0 trades
```

## Solution

### Corrected Ranges (WORKING ✅)
```python
'dist_below_ma_pct': 0.05-0.20  # 5-20% - REALISTIC
'tp_pct': 0.05-0.15             # 5-15% - REALISTIC
'sl_pct': 0.05-0.15             # 5-15% - REALISTIC
'time_stop': 5-20               # OK (unchanged)
'ma_len': 150-220               # OK (unchanged)
```

**Key Changes:**
1. **Increased `dist_below_ma_pct`** max from 15% to 20%
2. **Increased `tp_pct`** range from 2-5% to 5-15%
3. **Increased `sl_pct`** range from 1-3% to 5-15%
4. **Reduced `min_trades`** from 3 (200/yr scaled) to 5 (more realistic)

### Validation Test

## Lessons Learned

1. **Always validate ranges manually** before long optimizations
2. **Use grid search results** as baseline for ranges
3. **Start with known-working values** and expand gradually
4. **Quick test is essential** (saved us from another 8-hour wasted run)
5. **Domain knowledge matters**: 
   - BTC daily volatility ~5-10%
   - TP/SL < volatility = premature exits
   - MA distance must account for crypto volatility
